# Todo 앱 작업 티켓

> **기준:** 개발 명세서와 현재 구현을 대조한 로컬 티켓 목록. 외부 이슈 트래커에는 게시하지 않았다.
>
> 상태는 요청된 기능의 구현 상태를 뜻한다. 완료 표시는 현재 코드에서 확인했고, 미완료 표시는 아직 수행할 작업 또는 검증 작업이다.

## 01: Turso 기반 Todo CRUD

**What to build:** 사용자가 한 페이지에서 할 일을 만들고, 최신순으로 확인하며, 완료 상태를 바꾸거나 삭제할 수 있는 흐름.

**Blocked by:** None (can start immediately).

**Status:** 완료

- [x] Turso 접속 정보를 서버 환경변수에서 읽는다.
- [x] 첫 DB 접근 때 `todos` 테이블이 없으면 생성한다.
- [x] 할 일을 추가하고 목록을 최신순으로 표시한다.
- [x] 완료와 미완료를 전환하고 완료 제목에 취소선을 표시한다.
- [x] 할 일을 즉시 삭제하고 변경 후 페이지 데이터를 갱신한다.
- [x] 빈 목록과 DB 목록 로딩 상태를 표시한다.

## 02: 제목 입력 검증

**What to build:** 빈 제목이나 공백만 있는 제목, 200자를 넘는 제목이 저장되지 않도록 한다.

**Blocked by:** 01: Turso 기반 Todo CRUD.

**Status:** 완료

- [x] 제목 앞뒤 공백을 제거하고, 빈 값은 등록하지 않는다.
- [x] 서버 액션에서 200자 초과 입력을 거부한다.
- [x] 입력 폼에서도 브라우저 길이 제한과 필수 입력 표시를 제공한다.

## 03: Cache Components에서 DB 목록 스트리밍

**What to build:** 정적 페이지 셸을 먼저 제공하고 Turso 목록은 요청 시 가져와 화면에 스트리밍한다.

**Blocked by:** 01: Turso 기반 Todo CRUD.

**Status:** 완료

- [x] 비동기 DB 목록 접근을 `<Suspense>` 경계 안에 둔다.
- [x] 목록 로딩 fallback을 표시한다.
- [x] DB 결과를 캐시하지 않아 CRUD 변경 뒤 최신 목록을 읽는다.
- [x] Webpack 프로덕션 빌드에서 컴파일, 타입 검사, 정적 페이지 생성을 확인한다.

## 04: Todo 통합 테스트 추가

**What to build:** 테스트 DB를 사용해 사용자가 보는 CRUD 및 검증 결과를 자동으로 확인한다.

**Blocked by:** 01, 02, 03.

**Status:** 미완료 — 자동화 테스트가 없고 동작은 검증되지 않음.

- [ ] 할 일 생성 후 목록 표시와 최신순 정렬을 확인한다.
- [ ] 완료 표시와 되돌리기, 삭제 결과를 확인한다.
- [ ] 빈 제목, 공백 제목, 200자 제목, 201자 제목의 경계를 확인한다.
- [ ] 테스트 간 DB 상태가 격리되도록 한다.

## 05: 기본 Turbopack 프로덕션 빌드 검증

**What to build:** 지원되는 빌드 환경에서 기본 `npm run build`가 성공하는지 확인하고 앱 자체 오류가 있으면 수정한다.

**Blocked by:** 03: Cache Components에서 DB 목록 스트리밍.

**Status:** 미완료 — 현재 개발 환경의 Turbopack이 CSS 하위 프로세스 포트 바인딩 제한으로 중단되어 검증되지 않음.

- [ ] 포트 바인딩이 허용되는 CI 또는 개발 환경에서 기본 빌드를 실행한다.
- [ ] 빌드 실패 시 환경 제한과 앱 오류를 구분해 해결한다.
- [ ] 기본 빌드 결과를 작업 기록에 남긴다.

## 이 명세 범위에서 제외된 항목

- 로그인 및 사용자별 데이터 소유권은 최초 요구사항에 따라 범위에서 제외했다.
- 로그인 없는 공개 배포는 방문자 누구나 데이터를 바꿀 수 있으므로, 공개 배포 전 접근 제한 여부를 별도 결정해야 한다.
- 인라인 입력 오류 메시지와 DB 장애 안내 UI는 명세상 미구현이며 범위 밖이다.
