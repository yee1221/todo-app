# Todo 앱 개발 회고

## 세션 요약

Next.js 16.4.6, Turso, SQLite 호환 테이블로 로그인 없는 Todo 앱을 만들었다. 요구사항 협의 후 CRUD와 화면을 구현했고, 코드 리뷰에서 Server Action의 200자 서버 검증 누락을 찾아 보완했다. Cache Components 빌드 오류를 조사해 DB 목록을 `<Suspense>` 아래에서 요청 시 스트리밍하도록 바꿨다. 로컬 명세, 작업 티켓, 이 회고 문서를 정리했다.

## 잘 된 점

- 초기 인터뷰에서 로그인 여부, 필수 CRUD, 데이터 컬럼, 자동 테이블 생성, 완료 표시, 정렬 및 삭제 동작을 확정해 구현 범위를 명확히 했다.
- Next.js 버전 지침을 따라 설치된 Next.js 16 문서를 읽고 Cache Components와 Server Actions의 현행 규칙에 맞췄다.
- `.env.local`은 열거나 출력하지 않았고, Turso 인증값은 서버 전용 코드에서만 참조했다.
- DB 입력은 바인딩 파라미터를 사용하고, 서버 액션에서 입력과 ID를 검증했다.
- 코드 변경과 기존에 스테이징된 스킬 파일을 분리해 선택 파일만 커밋했다.
- 공개 배포 시 인증이 없는 앱의 데이터 조작 가능성을 명세에 기록했다.

## 마찰과 개선 기회

### 1. 입력 경계 검증을 자동화하지 않았다

브라우저 입력에는 200자 제한이 있었지만, 처음 구현된 서버 액션은 빈 값만 확인했다. 리뷰 과정에서 직접 POST로 브라우저 검증을 우회할 수 있음을 발견해 서버 길이 제한을 추가했다. 현재 테스트 스크립트나 자동 테스트가 없어 이 경계가 회귀할 수 있다.

**개선:** 200자와 201자, 빈 문자열과 공백 문자열을 앱 수준 입력 테스트로 고정하고 CI에서 실행한다.

### 2. 최초 페이지 구조가 Cache Components 프리렌더와 맞지 않았다

페이지 상단에서 DB 목록을 바로 기다려 프리렌더 오류가 발생했다. Next.js 16에서는 정적 셸과 런타임 데이터 영역을 분리해야 한다. 데이터 조회를 Suspense 경계 안으로 옮긴 뒤 Webpack 빌드가 성공했다.

**개선:** 새 Next.js 페이지에 uncached 데이터가 필요하면 첫 구현부터 비동기 서버 컴포넌트와 Suspense 경계를 함께 설계한다. 프로젝트의 Next.js 버전 문서를 먼저 확인하는 기존 AGENTS 규칙은 이 작업에 유효했다.

### 3. 기본 Turbopack 빌드 검증은 개발 환경 제한에 막혔다

기본 빌드는 Turbopack이 CSS 처리용 하위 프로세스를 만들고 포트에 바인딩하는 단계에서 `Operation not permitted`로 실패했다. 권한을 높여 재시도해도 동일했고, Webpack으로 전환한 빌드에서는 앱을 통과시켰다. 따라서 기본 Turbopack 빌드는 여전히 확인되지 않았다.

**개선:** CI나 개발 컨테이너에서 Turbopack 하위 프로세스의 포트 바인딩이 가능한지 확인한다. 빌드 실패 로그에 빌더와 OS 권한을 함께 기록해 코드 오류와 실행환경 오류를 빠르게 구분한다.

### 4. 유니코드 작업 경로를 반복해서 직접 입력했다

한국어 디렉터리를 도구 인자에 여러 번 직접 입력하면서 경로 정규화 차이로 명령 실행이 실패했다. 이후 기본 작업 디렉터리를 사용하자 해결됐다.

**개선:** 도구가 기본 작업 디렉터리를 제공하면 반복해서 절대 경로를 입력하지 않는다. 필요한 경우 `pwd`로 경로를 한 번 확인하고 셸에서 현재 디렉터리를 기준으로 작업한다.

### 5. 커밋을 위해 저장소 메타데이터 권한이 필요했다

작업 파일은 쓸 수 있었지만 `.git/index`는 기본 샌드박스에서 읽기 전용이라 커밋이 거부됐다. 이후 승인된 권한 상승으로 대상 경로만 커밋했고 기존 스테이징을 보존했다.

**개선:** 작업 환경에서 커밋이 필요한 경우 저장소 메타데이터 쓰기 경로가 어떻게 승인되는지 초기에 확인한다. 커밋 시에는 경로를 명시해 사용자 기존 스테이징을 보존한다.

## 자동화 및 저장소 가드레일

- `package.json`에는 ESLint 실행 스크립트가 있지만 전용 테스트 스크립트는 없다.
- 저장소에서 CI 워크플로와 pre-commit 설정을 찾지 못했다.
- 빌드는 TypeScript 검사를 수행하지만 Server Action의 동작 경계나 실제 Turso CRUD는 확인하지 않는다.

**개선 우선순위:** CRUD와 입력 검증 통합 테스트를 추가하고, CI에서 테스트·린트·기본 프로덕션 빌드를 실행한다. 기본 빌드의 현재 실행환경 문제는 CI에서 먼저 확인한다.

## 다음 실행에서 적용할 사항

1. 사용자 입력 제약은 UI 속성뿐 아니라 Server Action 경계에서도 검증하고 테스트한다.
2. Cache Components 사용 시 uncached 데이터는 처음부터 적절한 Suspense 경계 아래에 둔다.
3. 설치된 Next.js 버전의 로컬 가이드를 구현 전에 확인한다.
4. 빌더 실패는 애플리케이션 오류와 환경 권한 오류로 나눠 기록한다.
5. 명시적 파일 경로로만 커밋해 기존 staged 작업을 보존하고, 비밀 파일은 커밋 대상에서 제외한다.
