# Todo 앱 개발 명세서

> **기준:** 현재 저장소 구현 및 대화에서 합의한 요구사항을 기록한다. 구현됨, 의도적으로 제외됨, 미구현, 검증되지 않음의 상태를 구분한다.

## Problem Statement

사용자는 로그인 절차 없이 한 페이지에서 할 일을 관리하고 싶다. 할 일을 추가하고 목록을 확인하며 완료 상태를 표시하거나 되돌리고, 더 이상 필요하지 않은 항목을 삭제할 수 있어야 한다. 데이터는 브라우저 임시 상태가 아니라 Turso 데이터베이스에 보존되어야 한다.

추가 범위는 마감일과 D-day, 우선순위, 카테고리, 상태 필터, 제목 검색, 오늘 마감 보기, 전체 완료율이다. 현재 앱에 반영했으며 테스트와 검증 상태는 아래에 구분해 기록한다.

## Solution

한국어 단일 페이지 Todo 앱을 제공한다. 페이지는 할 일 입력 폼과 DB에서 읽어 온 목록을 보여준다. 할 일 생성·완료 전환·삭제는 Next.js Server Actions가 처리하며, 목록 데이터는 Turso의 SQLite 호환 DB에서 읽고 쓴다. 각 할 일은 선택적인 마감일, 우선순위, 카테고리를 저장한다. 사용자는 상태·제목·오늘 마감 조건으로 목록을 좁혀 보고 전체 완료율을 확인한다. 완료 항목은 목록에 남아 있고 제목에 취소선을 표시한다.

Next.js 16.4.6의 Cache Components 환경에서는 페이지의 정적 요소와 DB 의존 목록을 분리한다. DB 목록은 비동기 서버 컴포넌트에서 읽고 `<Suspense>`로 감싸 요청 시 스트리밍한다. 목록은 캐시하지 않아 새 변경 내용이 다음 렌더에 반영된다.

확장 구현은 기존 Turso 데이터와 CRUD를 보존하면서 필요한 필드만 추가한다. 입력된 마감일·우선순위·카테고리는 새로고침 뒤에도 유지되어야 한다. 검색과 목록 필터는 기존 Cache Components 데이터 흐름과 공존해야 한다.

## User Stories

1. 로그인하지 않은 단일 앱 사용자는 제목을 입력해 새 할 일을 추가할 수 있다.
2. 사용자는 저장된 할 일 목록을 볼 수 있다.
3. 사용자는 새로 추가한 항목을 목록의 맨 위에서 볼 수 있다.
4. 사용자는 할 일을 완료 상태로 바꾸고 체크 표시를 볼 수 있다.
5. 사용자는 완료 항목을 다시 미완료로 되돌릴 수 있다.
6. 사용자는 완료된 항목의 제목에 취소선이 표시되는 것을 볼 수 있다.
7. 사용자는 항목을 확인 대화상자 없이 즉시 삭제할 수 있다.
8. 사용자는 할 일이 없을 때 빈 목록 안내를 볼 수 있다.
9. 사용자는 목록을 불러오는 동안 로딩 안내를 볼 수 있다.
10. 사용자는 입력 제목이 비어 있거나 공백뿐일 때 항목이 저장되지 않도록 기대할 수 있다.
11. 사용자는 200자를 초과하는 제목이 저장되지 않도록 기대할 수 있다.
12. 배포 운영자는 Turso 접속 정보를 서버 환경변수로 제공하고 DB 연결을 구성할 수 있다.
13. 사용자는 할 일마다 선택적인 마감일, 우선순위(높음/보통/낮음), 카테고리(공부/일상/업무/기타)를 저장할 수 있다.
14. 사용자는 마감일까지 남은 일수 또는 이미 지난 날짜를 D-day로 확인할 수 있다.
15. 사용자는 전체, 진행 중, 완료 상태별로 할 일 목록을 볼 수 있다.
16. 사용자는 제목 검색으로 원하는 할 일을 찾을 수 있다.
17. 사용자는 오늘 마감인 할 일만 모아볼 수 있다.
18. 사용자는 전체 할 일 수 대비 완료된 할 일의 비율을 확인할 수 있다.

## Implementation Decisions

- **사용자 모델:** 로그인과 계정은 요구되지 않는다. 현재 데이터에는 사용자 소유자 필드가 없으므로 모든 방문자는 같은 `todos` 데이터 집합을 보게 된다.
- **화면:** 한국어 한 페이지에서 제목, 입력 폼, 할 일 목록, 남은 할 일 수, 빈 목록 안내를 제공한다. 레이아웃은 작은 화면에 대응한다.
- **할 일 생성:** 입력 폼은 `required`와 200자 `maxLength`를 사용한다. Server Action은 문자열을 앞뒤 공백 제거 후 저장하고, 빈 값 또는 200자를 초과한 값은 저장하지 않는다. 서버 검증이 최종 경계다. 현재 거부된 입력에 별도 오류 메시지는 표시하지 않는다.
- **완료 상태:** `done` 값을 전환해 완료/미완료를 모두 지원한다. 완료 항목을 삭제하거나 숨기지 않고 취소선으로 표시한다.
- **삭제:** 삭제 버튼은 확인 단계 없이 바로 삭제를 실행한다.
- **정렬:** 목록 조회는 `created_at` 내림차순이며, 같은 시각이면 증가하는 `id` 내림차순으로 정렬한다.
- **저장소:** `@libsql/client`로 Turso에 연결한다. 접속 주소는 `TURSO_DATABASE_URL`, 인증 토큰은 `TURSO_AUTH_TOKEN` 환경변수에서 서버 측에만 읽는다. 비밀값은 클라이언트 번들에 전달하지 않는다.
- **테이블 초기화:** 목록 조회와 각 변경 전에 `CREATE TABLE IF NOT EXISTS`를 실행한다. 모듈 인스턴스 내 초기화 Promise를 공유하며 실패하면 다음 DB 접근에서 재시도한다. 서버 프로세스나 인스턴스가 새로 시작되면 다시 확인한다.
- **데이터 구조:**

  | 컬럼 | SQLite 타입 / 제약 | 의미 |
  | --- | --- | --- |
  | `id` | `INTEGER PRIMARY KEY AUTOINCREMENT` | 자동 증가 식별자 |
  | `title` | `TEXT NOT NULL` | 할 일 제목 |
  | `done` | `INTEGER NOT NULL DEFAULT 0` | 완료 여부 (`0` 미완료, `1` 완료) |
  | `created_at` | `TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP` | DB 생성 시각 |

  신규 DB 스키마에는 다음 컬럼이 포함된다. 기존 DB는 하단의 증분 마이그레이션을 거쳐 같은 컬럼을 갖는다.

  | 컬럼 | 계획 정의 | 기존 행의 기본값 |
  | --- | --- | --- |
  | `due_date` | `TEXT NULL`, 날짜만 저장하는 `YYYY-MM-DD` | `NULL` (마감일 없음) |
  | `priority` | `TEXT NOT NULL DEFAULT 'normal'` (`high`, `normal`, `low`) | `normal` (보통) |
  | `category` | `TEXT NOT NULL DEFAULT 'other'` (`study`, `daily`, `work`, `other`) | `other` (기타) |

- **데이터 마이그레이션:** `CREATE TABLE IF NOT EXISTS`만으로 기존 테이블은 바뀌지 않으므로, 초기화 시 `PRAGMA table_info(todos)`로 누락 컬럼을 확인하고 없는 컬럼만 `ALTER TABLE ... ADD COLUMN`으로 추가한다. 테이블을 삭제/재생성하거나 기존 행을 초기화하지 않는다. 마이그레이션은 반복 실행에 안전하며, 일부 컬럼 추가 뒤 실패해도 다음 실행이 누락된 컬럼을 이어서 추가한다. 동시 초기화가 같은 컬럼을 추가한 경우 실제 스키마를 다시 확인한다. 기존 행은 마감일 없음, 보통 우선순위, 기타 카테고리로 읽힌다.

- **CRUD 계약:**
  - 목록: 테이블 초기화 후 모든 행을 최신순으로 읽고 `done`을 boolean으로 변환한다.
  - 생성: 제목을 바인딩 파라미터로 넣어 INSERT한다.
  - 완료 전환: 양수의 안전한 정수 ID를 받고 SQL에서 `0`/`1`을 반전한다.
  - 삭제: 양수의 안전한 정수 ID를 받고 해당 행을 삭제한다.
  - SQL 값은 모두 바인딩 파라미터를 사용한다.
- **변경 후 갱신:** Server Action이 성공하면 `/` 경로를 `revalidatePath`로 갱신한다.
- **Next.js 16 Cache Components:** `cacheComponents`와 `partialPrefetching`이 활성화되어 있다. 제목과 입력 폼은 프리렌더 정적 셸에 포함한다. DB 목록 조회는 캐시하지 않고 비동기 목록 컴포넌트에서 수행하며 `<Suspense>` fallback은 목록 로딩 표시를 제공한다. 따라서 Turso CRUD를 유지하면서 프리렌더가 DB 응답에 막히지 않는다.
- **기존 구현 경계:** 페이지 컴포넌트 → 목록 서버 컴포넌트 → 서버 전용 데이터 모듈 → Turso 흐름을 사용한다. 생성·완료·삭제는 Server Action → 데이터 모듈 → Turso 흐름을 사용한다.
- **오류 처리:** 환경변수가 없으면 DB 클라이언트 생성 단계에서 오류를 던진다. DB 연결/쿼리 오류를 사용자 메시지로 변환하는 별도 오류 UI는 현재 없다.
- **마감일·우선순위·카테고리:** 마감일은 날짜 전용 `YYYY-MM-DD` 값이며 없으면 `NULL`이다. 우선순위는 `high`/`normal`/`low`, 카테고리는 `study`/`daily`/`work`/`other` 값으로 저장하고 한국어 레이블로 표시한다. Server Action이 날짜와 열거값을 검증한다.
- **D-day:** `Asia/Seoul` 달력 날짜 차이로 계산한다. 오늘은 `D-Day`, 미래는 `D-1`, 지난 날짜는 `D+1` 형식으로 표시하며 마감일이 없으면 D-day를 표시하지 않는다.
- **검색 및 필터:** 전체/진행 중/완료 상태, 제목 부분 검색, 오늘 마감 조건은 교집합으로 적용한다. 오늘 마감은 `due_date`가 한국 시간 기준 오늘인 항목이다.
- **완료율:** 필터 결과가 아닌 전체 할 일을 분모로 계산한다. 전체가 0개면 0%로 표시한다.

## Testing Decisions

- 좋은 테스트는 내부 SQL 구현을 고정하기보다 사용자가 볼 수 있는 결과를 확인한다. DB를 격리한 통합 경계에서 생성 후 목록 표시, 최신순 정렬, 완료와 되돌리기, 삭제, 빈 제목 및 200자 초과 입력의 미저장을 확인한다.
- 주요 seam은 페이지와 Server Actions를 연결하고 테스트용 Turso/LibSQL DB를 사용하는 앱 수준 통합 테스트다. DB 어댑터의 바인딩과 스키마는 별도 단위 테스트가 필요해질 때 보완할 수 있다.
- 최초 구현 검토 당시에는 전용 테스트 스크립트나 자동화 테스트가 없었다. 현재는 저장소·입력·표시 규칙 테스트가 추가되어 아래 범위가 검증됐다.
- 자동 테스트는 기존 스키마에서 행 보존과 기본값, 신규 메타데이터 CRUD, 날짜·열거값·제목 검증, D-day 날짜 경계, 필터·검색 조합, 전체 목록 기준 진행률을 확인한다. 화면의 브라우저 동작을 포함한 end-to-end 테스트와 실제 배포 Turso DB 마이그레이션은 **검증되지 않음**이다.
- `npm run build -- --webpack`은 Next.js 16.4.6에서 컴파일, TypeScript 검사 및 정적 페이지 생성을 통과했다. 기본 `npm run build`의 Turbopack은 개발 환경에서 하위 프로세스의 포트 바인딩 제한으로 완료되지 않아 해당 경로는 **검증되지 않음**이다.

## Out of Scope

- 로그인, 사용자 계정, 사용자별 데이터 분리
- 여러 목록, 설명
- 할 일 제목 편집
- 완료 항목 자동 숨김 또는 일괄 삭제
- 삭제 확인 대화상자 및 잘못된 입력에 대한 인라인 오류 메시지
- 클라이언트 오프라인 저장 및 동기화
- 배포 플랫폼 구성

## Further Notes

### 구현 상태

- **구현됨:** 단일 페이지 입력/목록, 빈 상태, 로딩 fallback, 할 일 CRUD, 완료 취소선과 되돌리기, 최신순 정렬, 서버 측 빈 제목/200자 제한, Turso 환경변수 연결, 테이블 자동 생성, Cache Components용 Suspense 스트리밍.
- **의도적으로 제외됨:** 로그인 및 사용자별 소유권. 이는 최초 요구사항에서 로그인 불필요로 결정됐다.
- **구현됨:** 마감일/D-day, 우선순위, 카테고리, 전체/진행 중/완료 필터, 제목 검색, 오늘 마감 필터, 전체 완료율, 기존 행을 보존하는 증분 마이그레이션.
- **미구현:** 별도 인증/접근 제한, 공개 배포 시 데이터 보호 정책, 데이터베이스 오류·입력 거부 메시지 UI, 브라우저 end-to-end 테스트.
- **검증됨:** 기존 스키마 보존 및 신규 데이터 로직 테스트 7개, ESLint, Webpack 프로덕션 빌드.
- **검증되지 않음:** 배포된 Turso DB에 대한 실제 마이그레이션/CRUD, 브라우저 end-to-end, 기본 Turbopack 프로덕션 빌드. Webpack 기반 프로덕션 빌드는 통과했다.

### 배포 보안 주의

로그인이 없으므로 앱을 공개 배포하면 사이트에 접근할 수 있는 방문자가 Server Actions를 통해 공용 할 일 데이터를 추가·완료 전환·삭제할 수 있다. 현재 구조에는 사용자 인증이나 소유권 검사가 없다. 이는 합의된 단일 사용자 모델을 반영하지만, 공개 배포 전에는 접근 제한 여부를 별도로 결정해야 한다.

### 문서 게시

이 명세는 저장소의 로컬 문서로 작성했다. 저장소에 이슈 트래커 설정 문서가 없어 이슈 트래커에는 게시하지 않았다.
